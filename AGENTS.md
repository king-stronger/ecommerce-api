# AGENTS.md — ecommerce-api

Pareto ecommerce backend (Cloudflare Worker). Production-ready; prefer small, low-risk changes.

## Stack

- **Runtime**: Cloudflare Workers (`wrangler`), `nodejs_compat`
- **HTTP**: Hono + `@hono/zod-openapi` + Scalar (`/scalar`)
- **DB**: Neon Postgres (serverless) via `@neondatabase/serverless` + Drizzle ORM
- **Auth**: better-auth (email/password + admin plugin) at `/api/auth/*`
- **Validation**: Zod 4 (`drizzle-zod` for select schemas)
- **Lint/format**: Biome
- **Tests**: Vitest (Node), HTTP integration against a real Neon DB
- **Package manager**: pnpm

## Layout

```
src/
  app.ts                 # Mounts modules + OpenAPI
  auth.ts                # better-auth CLI entry only (Node); not imported by Worker
  lib/                   # create-app, env, auth factory, OpenAPI, types
  db/                    # db client, schema barrel, zod schemas, migrations, seed
  db/schemas/            # Drizzle table definitions
  middlewares/           # services (db/auth), auth route helpers
  modules/<name>/        # *.routes.ts, *.handlers.ts, *.schemas.ts, *.index.ts, *.test.ts
  services/              # Cart / checkout domain logic
  test/                  # Shared Vitest helpers + env
```

Modules today: `catalog`, `cart`, `checkout`, `admin`.

## Conventions

- Path alias: `@/*` → `src/*`. Prefer `.js` extensions in relative/alias imports (ESM).
- New HTTP feature = one module folder: define OpenAPI route → handler → wire in `*.index.ts` with `.openapi()`, then mount in `src/app.ts` if new.
- Public/guest routes: `optionalRoute`. Admin: `adminRoute` (session + `role` includes `admin`).
- Shared insert/update Zod lives in `src/db/zod.ts`; module `*.schemas.ts` re-export or add route-specific shapes.
- Money/stock are integers. Guest cart uses `cart_session` cookie (`src/services/cart-session.ts`).
- No payment-charge routes by design (payments table reserved for a future PSP).
- CORS + Better Auth trust `TRUSTED_ORIGINS` (comma-separated). Frontends must call with `credentials: "include"`.

## Do not edit by hand

| File / path | Regenerated by |
| --- | --- |
| `src/db/schemas/auth.ts` | `pnpm auth:generate` |
| `src/db/migrations/**` | `pnpm db:generate` |
| `worker-configuration.d.ts` | `pnpm types` |

`src/auth.ts` looks unused to static analyzers (Knip): keep it — it is the Better Auth CLI config (`pnpm auth:generate`).

## Tests

- Integration tests hit Neon via `DATABASE_URL_TEST` (preferred) or `DATABASE_URL`.
- Apply migrations on the test DB before `pnpm test`.
- Fixtures use `@ecommerce.test` emails and `test-ecom-*` slugs; clean up with `cleanupEcommerceFixtures` in `afterEach`.
- Helpers: `src/test/helpers.ts`. Suites run serially (`fileParallelism: false`).

## Pitfalls

- `app.route("/", route as never)` in `app.ts` is intentional (OpenAPIHono union size limits).
- On HTTPS `BETTER_AUTH_URL`, auth cookies are `SameSite=None; Secure` for cross-site storefronts.
- Local secrets live in `.env` only (gitignored). Wrangler production secrets: `wrangler secret put`. See `.env.example`.
- OpenAPI JSON is **runtime-generated** at `/docs` from route definitions — there is no checked-in spec to edit. Auth OpenAPI is separate: `/api/auth/open-api/generate-schema`.

## Change rules for agents

1. Do not refactor style-only or swap stack/deps without a concrete need.
2. Do not rewrite working code or add abstractions “for cleanliness”.
3. Prefer extending an existing module over new layers.
4. Keep behavior stable; cover new critical paths with the existing Vitest HTTP style.
5. After changes run: `pnpm typecheck`, `pnpm check`, `pnpm test`. There is no separate `build` script; Wrangler bundles on `dev`/`deploy`.
